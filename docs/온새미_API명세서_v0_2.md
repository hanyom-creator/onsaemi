- 작성일: 2026-09-22
- 작성자: 고하영
- WBS: 1.2.3 API 명세 · SQLite 스키마 · 아키텍처 설계도
- 상태: 개정 — 청크 업로드 방식을 스트리밍 인식 방식으로 전환
- 관련 문서: docs/LEVEL_STATES.md (v1.2), docs/RISK_WEIGHTS.md (v1.3)

## 1. 개요

보조폰 앱이 Google 스트리밍 음성 인식에 직접 연결해 통화 음성을 끊김 없이 인식한다. 서버는 소리를 받지 않고 인식된 문장만 받아 마스킹 · 위험 판정 · 대본 생성을 수행하고, 결과를 SSE로 앱에 보낸다.

v0.1의 2초 청크 업로드 방식은 청크 경계에서 단어가 잘려 잘못 인식되는 문제(실측: 17단어 중 경계 오류 3개)가 있어 폐기한다.

| 구분 | 내용 |
|---|---|
| Base URL (개발) | `http://127.0.0.1:8000` 또는 `https://<ngrok-id>.ngrok-free.app` |
| Base URL (운영) | `https://<ec2-ip>.nip.io` (AWS 서울 리전) |
| 인코딩 | UTF-8 |
| 시각 형식 | ISO 8601 (`2026-09-22T14:32:10.123+09:00`) |

### 1.1 전체 흐름

```
[주폰] 통화 (스피커폰)
   ↓ 음성
[보조폰] 마이크 캡처
   ├─ ① POST /token → 10분짜리 토큰 수신
   ├─ ② Google 스트리밍 인식에 직접 연결 (토큰 사용)
   │     ↓ 중간 결과 · 최종 결과
   └─ ③ POST /utterances (중간 결과 1초마다 최신 1건, 최종 결과는 즉시)
[서버] 마스킹 → 듣는 중: 키워드 → 대본 뼈대 준비
              → 말이 끝남: 신호 확정 → 점수 · 레벨 → 대본 (뼈대 재사용 또는 새로 생성)
   ↓ SSE
[보조폰] 오버레이 표시 (Lv1~Lv5)
```

## 2. 공통 규약

### 2.1 인증

모든 요청에 `X-API-Key` 헤더를 사용한다.

| 환경변수 `API_KEY` | 동작 |
|---|---|
| 비어 있음 | 검증 생략 (로컬 개발 구간) |
| 값 존재 | 헤더와 대조, 불일치 시 `401` (EC2 운영 구간) |

토큰 발급(4.1)은 Google 음성 인식 사용 권한을 넘겨주므로, EC2 운영 구간에서는 반드시 값을 채운다.

### 2.2 세션 식별자

- 앱이 통화 감지 즉시 UUID v4를 생성한다.
- 서버는 처음 보는 `session_id`로 요청이 오면 세션을 자동 생성한다. 첫 요청은 보통 토큰 발급(4.1)이다.

### 2.3 발화 식별자

| 필드 | 의미 |
|---|---|
| `utt_seq` | 발화 번호. 0부터 시작, 최종 결과가 나올 때마다 1 증가. 진행 중인 발화의 중간 결과는 같은 번호를 쓴다 |
| `rev` | 같은 발화 안에서 중간 결과의 순번. 0부터 증가, 최종 결과도 이어서 증가 |

서버는 같은 `utt_seq`에서 이미 받은 `rev` 이하가 다시 오면 무시한다 (재전송 · 순서 뒤바뀜 대비).

### 2.4 오류 응답

```json
{ "error": "invalid_api_key", "message": "API 키가 올바르지 않습니다" }
```

| 코드 | 상황 |
|---|---|
| 400 | 필수 필드 누락, 형식 오류 |
| 401 | API 키 불일치 |
| 404 | 종료된 세션에 요청 |
| 429 | 토큰 발급 한도 초과 |
| 500 | Google 토큰 발급 · LLM 호출 실패 |

## 3. 보안 구성

앱에는 Google 키를 두지 않는다. 앱을 분해해도 키를 얻을 수 없고, 토큰이 유출되어도 짧은 시간 · 음성 인식 권한으로만 피해가 제한되도록 역할을 나눈다.

### 3.1 Google 계정 역할 분리

| 계정 | 키 보관 위치 | 권한 | 역할 |
|---|---|---|---|
| `onsaemi-token-issuer` | 서버(EC2)에만 | `onsaemi-speech`에 대한 토큰 생성 권한만 | 토큰을 만들어 주는 계정 |
| `onsaemi-speech` | 키 없음 | 음성 인식 사용(Cloud Speech Client)만 | 앱이 실제로 쓰는 계정 |

서버는 `onsaemi-token-issuer`로 `onsaemi-speech` 이름의 토큰을 수명 10분으로 발급한다. `onsaemi-token-issuer` 키가 유출되어도 음성 인식 토큰만 만들 수 있고, 다른 Google 자원에는 접근할 수 없다.

### 3.2 앱의 토큰 취급

- 토큰은 메모리에만 두고 파일 · 로그에 남기지 않는다.
- 통화가 끝나면 즉시 버린다.

### 3.3 피해 한도

| 항목 | 설정 |
|---|---|
| Google Cloud 예산 알림 | 월 예산의 50% · 90% · 100%에서 알림 |
| 음성 인식 호출 한도 | 분당 요청 수를 검증에 필요한 수준으로 제한 |
| 토큰 발급 한도 | 세션당 3회 |

토큰 수명 10분은 세션 상한 5분(8장)보다 길어서, 정상 흐름에서는 세션당 1회 발급으로 충분하다. 3회 한도는 재시도 · 재연결을 위한 여유분이다.

한도를 초과하면 앱은 "보호 기능이 일시 중지됐어요"를 표시하고 추가 토큰 요청을 멈춘다. 서버는 초과 사실을 기록한다.

### 3.4 범위 밖

- Google Play Integrity로 "정품 앱에서 온 요청인지" 확인하는 기능은 Play 스토어 배포가 전제라 이번 범위에서 제외한다 (9장).

## 4. 엔드포인트

### 4.1 POST /sessions/{session_id}/token

Google 스트리밍 인식용 토큰 발급. 앱이 통화 감지 직후 1회 호출한다.

**요청** — 본문 없음

**응답** — `200 OK`

```json
{
  "access_token": "ya29....",
  "expires_at": "2026-09-22T14:42:10+09:00",
  "expires_in": 600,
  "stt_config": {
    "language_code": "ko-KR",
    "encoding": "LINEAR16",
    "sample_rate_hertz": 16000,
    "interim_results": true
  }
}
```

`stt_config`를 서버가 내려줘서, 인식 설정을 바꿀 때 앱을 다시 빌드하지 않아도 된다.

---

### 4.2 POST /sessions/{session_id}/utterances

인식 결과 업로드. 중간 결과와 최종 결과를 같은 엔드포인트로 보낸다.

**요청** — `application/json`

```json
{
  "utt_seq": 3,
  "rev": 5,
  "is_final": true,
  "text": "지금 바로 안전계좌로 자산을 옮기셔야 합니다",
  "confidence": 0.91,
  "result_end_ms": 18420,
  "received_at": "2026-09-22T14:32:28.410+09:00"
}
```

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `utt_seq` | int | O | 발화 번호 (2.3) |
| `rev` | int | O | 발화 내 순번 (2.3) |
| `is_final` | bool | O | 최종 결과 여부 |
| `text` | string | O | 인식 문장 (마스킹 전 원문) |
| `confidence` | float\|null | O | 인식 신뢰도. Google은 최종 결과에만 값을 주므로 중간 결과는 `null` |
| `result_end_ms` | int | O | 스트림 시작부터 이 결과의 끝까지의 시간(ms). Google이 주는 값 |
| `received_at` | string | O | 앱이 Google에서 이 결과를 받은 시각 |

**응답** — `202 Accepted`

```json
{ "utt_seq": 3, "rev": 5, "accepted": true }
```

분석 결과를 기다리지 않고 즉시 응답한다. 결과는 SSE로 전달한다.

**전송 규칙**

- 중간 결과: 1초에 최대 1건, 그 시점의 최신 결과만 보낸다.
- 최종 결과: 받는 즉시 보낸다. 중간 결과 전송 간격과 무관하다.

이 스로틀은 앱이 지키는 규칙이다. 서버는 받은 요청을 모두 처리하며, 별도로 걸러내지 않는다.

---

### 4.3 GET /sessions/{session_id}/stream

분석 결과 수신용 SSE 연결. 앱이 통화 시작 시 연결한다.

**응답 헤더**

```
Content-Type: text/event-stream
Cache-Control: no-cache
```

모든 이벤트는 `id`(세션 안에서 1씩 증가)와 `event`(종류)를 가진다.

```
id: 42
event: analysis
data: { ... }
```

#### 이벤트 종류

**`analysis`** — 최종 결과 1건의 분석 결과

```json
{
  "utt_seq": 3,
  "transcript": "지금 바로 안전계좌로 자산을 옮기셔야 합니다",
  "signals": ["이체요구"],
  "score_delta": 20,
  "risk_score": 75,
  "level": 2,
  "level_reason": "score",
  "script_id": 7,
  "script": "제가 대표번호로 다시 걸어서 확인하겠습니다. 성함과 소속이 어떻게 되시죠?",
  "script_source": "draft",
  "script_followed": null,
  "latency_ms": { "server": 820, "end_to_script": 1650 }
}
```

| 필드 | 설명 |
|---|---|
| `transcript` | 마스킹 처리된 문장 |
| `signals` | 이번 발화에서 확정된 위험 신호 |
| `score_delta` | 이번 발화로 오른 점수 |
| `risk_score` | 누적 점수 0~100 |
| `level` | 0~5 |
| `level_reason` | 아래 표 |
| `script` | 대본. 65점 미만이면 `null` (강제 승급 Lv5는 예외) |
| `script_source` | `draft`(뼈대 그대로) / `filled`(뼈대 빈칸 채움) / `new`(새로 생성) / `null` |
| `script_followed` | 직전 대본 이행 판정 (LEVEL_STATES.md) |
| `latency_ms.server` | 서버가 최종 결과를 받은 뒤 결과를 만들기까지 |
| `latency_ms.end_to_script` | 발화가 끝난 시점부터 대본 완성까지 (6.3.3 종단 지연 지표) |

**`script_chunk`** — 대본을 만들어지는 대로 흘려 보냄 (`script_source`가 `new`일 때)

```json
{ "script_id": 7, "text": "제가 대표번호로", "done": false }
```

앱은 같은 `script_id`의 `text`를 이어 붙여 표시한다. `done: true` 뒤에 같은 `script_id`의 `analysis`가 온다.

**`level`** — 발화 없이 시간 경과로 레벨이 바뀜

```json
{ "level": 2, "risk_score": 65, "level_reason": "decay" }
```

**`session_ended`** — 세션 종료

```json
{ "end_reason": "app_notified" }
```

#### `level_reason` 값

| 값 | 의미 |
|---|---|
| `score` | 점수가 상위 구간에 진입 |
| `sensitive_pattern` | 사용자 민감정보 발화로 즉시 Lv5 |
| `critical_repeat` | 정말 위험한 말 3회로 즉시 Lv5 |
| `timeout` | Lv2 탐침 후 30초 무반응으로 Lv3 |
| `decay` | 30초 무신호로 한 단계 하강 |

#### 놓친 결과 재전송

- 연결이 끊겼다가 다시 연결할 때 앱은 `Last-Event-ID` 헤더에 마지막으로 받은 `id`를 담는다.
- 서버는 그 뒤의 이벤트를 순서대로 다시 보낸 뒤 실시간 전송을 이어간다.
- 서버는 보낸 이벤트를 DB 이벤트 기록 테이블에 번호와 함께 저장한다 (세션 안에서 1씩 증가, 서버 재시작에도 유지). `script_chunk`는 저장 · 재전송하지 않는다 (완성 대본은 `analysis`에 들어 있음).

---

### 4.4 POST /sessions/{session_id}/end

앱의 통화 종료 통보.

**요청**

```json
{ "ended_at": "2026-09-22T14:38:22+09:00", "last_utt_seq": 41 }
```

**응답** — `200 OK`

```json
{ "session_id": "a3f2...", "total_utterances": 42, "max_risk_score": 78, "max_level": 3 }
```

**세션 종료 조건**

| 경로 | 조건 | `end_reason` |
|---|---|---|
| 앱 통보 | `POST /end` 수신 | `app_notified` |
| 연결 끊김 | SSE 연결이 60초 이상 없음 | `stream_timeout` |
| 세션 상한 | 세션 생성 후 5분 (검증용, 9장) | `session_limit` |

v0.1의 "마지막 청크 후 60초"는 쓰지 않는다. 스트리밍 방식에서는 침묵 중에 보낼 것이 없어, 무발화를 종료로 오판할 수 있기 때문이다. 앱이 살아 있는지는 SSE 연결로 판단한다.

## 5. 분석 흐름

사람이 상대 말을 들으면서 대답의 방향을 미리 잡고, 말이 끝나면 곧바로 대답하는 방식을 따른다.

### 5.1 듣는 중 (중간 결과)

```
중간 결과 → 마스킹 → 키워드 검사 (코드) → 위험 키워드 발견 시 GPT로 대본 뼈대 준비
```

- 키워드 목록은 서버 설정으로 관리한다.
- 뼈대는 빈칸이 있는 대본 형태로 만든다. 예: "제가 ○○ 대표번호로 다시 걸어서 확인하겠습니다"
- 뼈대 준비는 발화당 1회로 한다.
- **점수는 올리지 않는다.** 중간 결과는 글자가 바뀔 수 있어, 점수는 5.2의 확정 신호로만 올린다.

### 5.2 말이 끝남 (최종 결과)

```
최종 결과 → 마스킹 · 민감정보 검사 → GPT 위험 신호 확정 → 점수 · 레벨 계산 (LEVEL_STATES.md, RISK_WEIGHTS.md)
         → 대본 필요 시: 뼈대가 맞으면 그대로(draft) 또는 빈칸만 채움(filled), 안 맞으면 새로 생성(new, 흘려 보냄)
         → SSE analysis
```

- 민감정보가 감지되면 GPT 판정을 기다리지 않고 즉시 Lv5로 올린다.
- 대본이 필요한 경우: Lv2 이상, 또는 강제 승급 Lv5.

## 6. 끊김 처리

| 연결 | 처리 |
|---|---|
| 앱 → Google (스트리밍 인식) | 앱이 최근 3초 소리를 메모리에 보관한다. 끊기면 즉시 다시 연결하고, 보관한 소리부터 이어서 보낸다. 토큰이 만료됐으면 4.1로 재발급한다 |
| 앱 → 서버 (4.2 업로드) | 실패 시 1초 → 2초 → 4초 재시도 (최대 3회). 3회 실패하면 앱에 보관하고 다음 결과로 진행한다. 연결이 복구되면 보관분을 `utt_seq`, `rev` 순서대로 보낸다. 보관분 중 중간 결과는 같은 발화의 최종 결과가 있으면 버린다 |
| 서버 → 앱 (4.3 SSE) | 끊기면 `Last-Event-ID`로 다시 연결해 놓친 이벤트를 받는다 (4.3) |

## 7. 민감정보 처리

마스킹 파이프라인(3.1.3)은 서버에서 동작하며, 중간 결과와 최종 결과 모두 GPT · DB · SSE로 가기 전에 거친다.

```
인식 문장 → ① 패턴 탐지 → ② 신호 기록 → ③ 치환 → GPT · DB · SSE
```

| 구분 | 패턴 | 처리 |
|---|---|---|
| 사기범 측 | 수취 계좌번호, 기관 사칭 전화번호 | 위험 신호 (`수취계좌제시`) |
| 사용자 측 | 카드번호, 주민등록번호, CVC, 인증번호 | 즉시 Lv5 (`sensitive_pattern`) |

**스트리밍에서 추가로 고려할 점**

- 번호를 말하다 멈추면 최종 결과가 둘로 나뉠 수 있다. 직전 최종 결과의 끝부분을 이어 붙여 함께 검사한다.
- 인식 결과에 숫자가 한글("일이삼사", "공일공")로 나올 수 있다. 패턴은 숫자와 한글 숫자를 모두 잡는다.

**마스킹의 목적**은 해외 LLM API로의 개인정보 국외 이전을 최소화하는 것이다. 통화 음성은 Google 음성 인식으로 직접 전송되며, 마스킹은 그 이후의 문장 단계에 적용된다. 사용자를 사기범으로부터 보호하는 역할은 Lv1~Lv5 에스컬레이션이 맡는다.

## 8. 검증용 설정값과 운영 시 고려 사항

아래 값은 데모 · 실험에서 동작을 증명하기 위한 설정값이며, 실제 통화 길이나 운영 환경을 가정한 값이 아니다.

| 항목 | 검증용 값 | 운영 시 필요한 것 |
|---|---|---|
| 토큰 수명 | 10분 | 통화 도중 만료 전 재발급 |
| 세션 상한 | 5분 (API 비용 방어) | 상한 해제 또는 조정 |
| Google 스트림 | 스트림 1개 (Google 제한 5분) | 5분마다 스트림을 끊김 없이 이어 여는 처리 |
| 소리 보관 (재연결용) | 최근 3초 | 네트워크 환경에 맞춰 조정 |
| 중간 결과 전송 간격 | 1초 | 실측 후 조정 |
| 소리 전송 단위 (앱 → Google) | 100ms | — |
| 토큰 발급 계정 키 | EC2에 키 파일 보관 | AWS → Google 키 없는 연동(Workload Identity Federation)으로 키 파일 제거 |
| 요청 앱 확인 | `X-API-Key` | Google Play Integrity |

검증 범위에서는 토큰 재발급과 Google 스트림 이어 열기를 구현하지 않는다. 모든 통화는 세션 상한 5분 안에서만 동작을 보장한다.
